# Test suite

Written **test-first**: the tests encode the contracts in `docs/` before the code exists. Until the milestone that implements each area lands, its tests fail with "module not found". That is expected. Nothing here has been run yet.

| Layer | Path | Tool | Needs | Milestone |
|---|---|---|---|---|
| Unit (pure domain) | `branch-server/tests/unit/*` | Vitest | nothing | M1 |
| Database (schema, constraints, triggers, seed) | `branch-server/tests/db/*` | Vitest | nothing | M1 (done) |
| Integration (HTTP + a throwaway SQLite file) | `branch-server/tests/integration/*` | Vitest + Supertest | nothing | M1–M3 |
| Migration / ETL, parser and time conversion | `branch-server/tests/migration/*`, `branch-server/tests/unit/etl-*` | Vitest | `etl.test.ts` needs `POSDB.sql` (`POSDB_DUMP=path`, skipped without it); `etl-synthetic.test.ts` and the unit tests need nothing | M2 (done) |
| Web logic (cart, payment analysis, catalog cache, outbox) | `till/web/tests/*` | Vitest | nothing | M3 (done) |
| End-to-end on the built app, with the real security headers | `till/tests/e2e-prod/*` | Playwright (`production-build` project; builds the app first) | nothing | M5 (done) |
| End-to-end (real browser at 1366×768) | `till/tests/e2e/*` | Playwright | nothing: it starts a throwaway API (`branch-server/src/cli/e2e-server.ts`, fake printer) and the web app itself. `screenshots.spec.ts` only runs with `SHOTS=<folder>` | M3 (done) |
| Load | `branch-server/tests/load/run.ts` (`npm run test:load`, `-- --quick` for a fast pass) | Plain Node (no tool to install) | nothing: it imports `POSDB.sql` into a temporary copy, starts the real server in production mode, and deletes everything afterwards | M5 (done) |
| Query plans (the busy queries use their indexes) | `branch-server/tests/db/query-plans.test.ts` | Vitest | nothing | M5 (done) |

## Run

```bash
npm i
npm run test:unit
npm run test:db
npm run test:integration       # each test file gets its own temporary SQLite database
POSDB_DUMP=./POSDB.sql npm run test:migration
npx playwright install && npm run test:e2e
npm run test:load              # imports POSDB.sql into a temporary copy, ~5 minutes; add -- --quick for ~2
npm run test:e2e               # also runs the built app under the real security headers (project "production-build")
```

## Manual hardware checklist (before go-live)

- [ ] Scanner reads EAN-13, EAN-8, a damaged label, and 20 scans back-to-back with no dropped or merged codes.
- [ ] Printer (USB, English only): 42-column alignment, a product with an Arabic name prints a readable transliterated name, cut works, drawer opens on cash. Check 80 vs 58 mm.
- [ ] Pull the printer's power mid-sale: the sale is saved and the warning appears.
- [ ] Stop the API service mid-sale: the sale is kept in the outbox and syncs once after the service restarts.
- [ ] Power-cycle the server during a sale: no half-written sale in the DB.
- [ ] Restore last night's backup onto a clean machine and open it.
